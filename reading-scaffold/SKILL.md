# 读书前框架（按书生成）

## 这是什么

在**翻开一本书之前**用。用户**只报书名**，你现场为**这一本书**生成一份一页纸框架。换一本书就重新生成一份，不做通用清单。

三段时间轴：

| 什么时候 | 问谁 | 三块 |
|---|---|---|
| 翻开之前 | 我和这本书的关系 | what / why / how |
| 读的过程中 | 每一章 | 每章 2–3 个白话问题 |
| 读完之后 | 这本书本身 | what / why / how |

**框架只出问题，不出答案。** 答案全部由用户自己写——这是他读书时的工作。

生成后**必须落成一个 markdown 文件**，不能只在对话里给一遍就算完。规则见「落盘规则」。

## 铁律

1. **白话。** 任何一个需要先想一下"这词什么意思"的词，都不许出现。见下方对照表。
2. **不做内容预设。** 框架不能假设用户已经知道书里写了什么——每个空位都留给他填。但**元信息是你的活**：副标题、目录、作者、版次这些翻开书就能看到的东西，由你自己补，不要叫用户提供。
3. **只出问题，不给答案。** 不要替用户写"这本书讲的是……"，也不要顺便剧透作者的观点、结论、立场。
4. **不剧透，但可以给目录。** 你就算知道这本书，也不许把它说了什么讲出来——那会让用户失去自己读出来的机会。**结构信息（副标题、目录、作者）可以给，作者的观点和结论不可以给**，这两件事不冲突。
5. **拿不准就留空，绝不编。** 目录记不准就不写，宁可标 `待补`。编一份假目录比留空糟得多——整份框架会跟着歪。
6. **一页纸。** 长了就不会用。宁可少问，不许抻长。
7. **一页对一本书。** 用户一次给多本，就一本一份，不许合并。

## 起手动作

**用户只报书名，别的不用他给。** 你的第一件事是确认"是哪一本书"：

1. **书名唯一、你有把握** → 直接生成，不要再追问任何东西。
2. **书名有歧义**（同名书、多个译本、烂大街的书名）→ **只问一件事：作者是谁**。把你猜的候选摆出来让他点头（作者 + 这本书大概属于哪一块，一句话即可）。**用户确认之前不许生成。**
3. **书名你不认识、或拿不准是哪本** → 直说"这个书名我拿不准是哪一本"，请他补一句作者或出版社。**不许硬猜一本。**

确认之后，**副标题、作者、目录、版次你自己补上**，这些不该由用户提供。补的时候守两条：

- 目录**尽量用真实的章节标题原文**，不要改写、不要概括、不要意译。
- **只有有把握的才写。** 记不准的单章标 `第 X 章（标题我记不准）`，整段拿不准就标 `待补`，并请用户翻书时对一眼。**宁可留空，绝不编。**
- 框架开头带一句提醒："目录是我按记忆写的，你翻开书对一眼，对不上告诉我改。"

结构信息可以给，作者的结论不可以给（见铁律 4）。

## 用词对照（左边一律不许出现，用右边）

| 不许写 | 换成 |
|---|---|
| 靶子 | 作者在反对什么观点 |
| 命题 / 论点 | 作者想说的话 / 他想让大家接受什么 |
| 机制 | 为什么会这样，中间经过哪几步 |
| 承重概念 | 真正的关键词 |
| 张力 | 里头有个什么矛盾 |
| 边界条件 | 什么情况下就不成立了 |
| 删除测试 | 把这个词拿掉，这本书还站得住吗 |
| 论证 / 论证链 | 他是怎么讲这个道理的 |
| 现象 / 案例 | 他讲的是哪件事 / 他举的例子 |
| 综述 / 学术位置 | 他是在接着谁的话说 |

## 输出模板（照这个填，标题就是书名）

````markdown
# 《书名》· 读书框架

- 作者：______
- 开始读：______　读完：______

## 一、翻开之前：我和这本书

**what｜这大概是本什么书**
- 只看书名和副标题，我猜它讲的是：______
- 我猜它属于哪一类（讲一个现象 / 提出一个说法 / 反驳某个流行看法 / 提供一堆材料）：______
- 我猜书里会反复出现哪几个词：______

**why｜我为什么现在读它**
- 我想从它这里拿到什么：______
- 我手上有什么问题，指望它来回答：______

**how｜我打算怎么读**
- 哪些部分快读、哪些慢读：______
- 读的时候我要一直盯住的问题：______
- 打算几次读完、每次读多少：______

---

## 二、读的过程：每一章

> 读到对应章节时回来答一下，答不出来就先跳，不卡住。

**第 1 章「目录原文」**
- 这一章在讲什么（一句话）：______
- 它是在讲道理，还是在举例子：______
- 跟上一章是什么关系：______

**第 2 章「目录原文」**
- ……（同上三问）

---

## 三、读完之后：这本书

**what｜这本书讲的是什么**
- 一句话：______
- 真正的关键词（最多 3 个）：______

**why｜作者为什么要讲这件事**
- 作者在反对什么观点：______
- 他希望读者接受什么：______
- 他说清楚这件事为什么重要了吗：______

**how｜作者给了什么样的解决方案**
- 给了 → 是什么：______
- 没给 → 他是明确拒绝给，还是这本书本来就不为了给方案：______

**最后一栏（读完必答）**
- 我能不能用一分钟把这本讲给别人听：______
- （可选）跟讲过同一件事的另一本比，他说得不一样在哪：______
````

## 落盘规则

**一本书一个文件，全程只用这一份，读完也不另开。**

- **位置**：当前工作目录下的 `读书框架/` 文件夹（不存在就建）。用户指定了别处就听用户的。
- **文件名**：`《书名》读书框架.md`。
  - 书名里的 `/` 和 `:` 会把文件名弄坏，换成全角或短横。
  - 只用主书名，副标题不进文件名。
  - 同名书要在文件名里带上作者，免得两份框架撞名互相盖掉。
- **三段装同一个文件**：第二段、第三段不是新文件，是**往同一个文件里补**。目录补进来了，就只改第二段那一段，别整篇重写。
- **只写问题和空位**，绝不预填答案。用户答过的内容要写回文件时，**问题原文必须留在答案上面**，不许把问题删掉只留答案。
- **文件已存在**（重读、之前建过、二次阅读）→ **不许覆盖**。先读一遍，再问用户：接着往里填，还是在文件末尾新起一份"第 N 次读"。
- 写完把**完整路径**报给用户，让他知道东西在哪。
- 用户说不用落文件，就听他的，只在对话里给。

## 第二段（每章问题）怎么生成

- 每一章的**标题原文照抄**，别改写、别翻译、别概括成你自己的说法。
- 三问固定：这一章在讲什么 / 是在讲道理还是举例子 / 跟上一章什么关系。
- 允许按本章标题微调第三问，例如标题里带着明显转折或收尾意味时，可改成"这一章是不是要收口了"。但**不许加第四问**，也不许写出你对这一章内容的判断。
- **目录超过 8 章时合并**：按目录自己的分组（部分、篇、卷）折成 4–6 个块，每块 2–3 问，块名用目录里的原文。全书问题总数不超过 15 个。
- 目录章节标题本身也看不懂（只有编号没有标题）时，写"第 X 章（目录无标题）"，别去猜它讲什么。

## 第三段怎么用

用户通常读完才回来。做法：

1. 让他先凭记忆填，不许翻书。
2. 填完再翻书对一遍，**只对第三段**，看他哪里想错了。
3. 只有用户明确问"作者到底怎么说的"，才讨论书的内容；否则只帮他理顺他自己写的东西。

## 边界情况

- **用户只要框架、不想被引导** → 直接出模板，不追问。
- **书很冷门你不了解** → 先请用户确认是哪一本（作者或出版社）；确认之后如果仍然拿不到可靠目录，就只出第一段和第三段，第二段标 `待补`，说明"这本的目录我手上没有可靠的，你翻书对一眼再补"。**一句都不许编。**
- **用户中途要你总结这本书** → 拒绝剧透，改为"我们把第三段的空填一下，你来说，我帮你理顺"。
- **用户只报了书名** → 见「起手动作」：文件先建，第二段留 `待补`。
- **用户要的是通用清单**（"给我一份不管什么书都能用的"）→ 说明这个 skill 是**按书生成**的，一页对一本书；通用清单会让所有书长成一个样，那正是他上次不要的东西。
- **用户抱怨记不住** → 不要安慰，直接说病根：读完能复述才是读过，所以第三段那几栏不能不填。
- **用户嫌某个问题没用** → 直接删掉那一栏，不辩护。这份框架是给他用的。
