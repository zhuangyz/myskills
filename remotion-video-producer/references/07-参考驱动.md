# 参考驱动

写实题材没有绝对标准，只有"像不像"。参考图的作用是**把"我觉得差不多"变成"和这张比"**。

## 什么时候必须有

- 质感档位是写实 / 半写实
- 题材是自然物（水、火、植物、动物、矿物）
- 有明确摄影风格要求（水下、胶片、夜景、纪实）

图形化 / 风格化档位不需要。

## 选参考四条

| 条件 | 说明 |
|---|---|
| 同题材同介质 | 水下就找真实水下照片，不要拿"水下 CG 概念图" |
| 同光位 | 逆光对逆光，顶光对顶光 |
| 同景别 | 近景对近景。拿全景当近景的参考，雾和景深全错 |
| 必须是实拍 | **拿 CG 当参考 = 拿别人的毛病当标准** |

**一张就够。** 多张会互相打架，你会在两个目标之间来回改。

## 从参考里量什么

自动量五项（`--compare`）：

| 项 | 抓什么 |
|---|---|
| 平均亮度 YAVG | 整体曝光 |
| 平均饱和度 SATAVG | 脏 / 艳 |
| 动态范围 | 对比度、雾的厚度 |
| **R/G 通道比** | **红光残留——水下、雾天、黄昏的关键** |
| **B/G 通道比** | 色温偏移 / 介质吸收 |

人工看三项：

1. **层次**：前景 / 中景 / 远景各占多少，有没有遮挡
2. **颗粒**：噪点密度与大小
3. **暗部**：是死黑还是有色偏

## 怎么用

```bash
node scripts/assert.mjs --project . --stage g2 --compare out/cover.png --ref reference/ref.jpg
```

产出：

- `out/compare.png` —— 参考与成品并排，各 960 宽
- 五项数值与偏差，超容差判 FAIL；任一项测不出也判 FAIL

容差：亮度 ±12、饱和度 ±15、动态范围 ±20、通道比 ±0.12。

## 实测数据（珊瑚礁项目）

成品 `final-closeup.png` 自己和自己比：

```
R/G = 1.030   B/G = 0.859
```

真实水下照片（5 米以上）通常在 **R/G 0.5–0.8、B/G 1.0–1.3**。也就是说这帧的红光几乎没有被水吸收——一眼看去就是"陆地打灯拍的模型"，而不是海底摄影。

这就是参考驱动能抓、而其他所有检查项都抓不到的东西。

## 用途边界

**参考定"调子"，不定"形体"。**

参考能告诉你"珊瑚不对"，但不能告诉你"珊瑚该怎么建"。形体要靠资产、分形生成、或者换路径（真实素材/AI 视频模型）。

别把参考当成万能尺：五项统计全过、形体还是一堆圆柱体，参考也救不了。

## 三种常见失败

1. **拿好看的 CG 当参考** —— 两边的毛病会互相确认，越改越偏
2. **只在最后对比一次** —— 应该每镜静帧都比，越早发现越便宜
3. **拿不同景别的照片** —— 全景参考的雾浓度，套到近景上必然过重
