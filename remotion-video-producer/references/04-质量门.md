# 质量门

G3 / G4 / G5 用。清单不是想出来的，是被片子打出来的。

## 十项逐镜自检（G3）

| # | 项 | 判定方式 |
|---|---|---|
| 1 | 单屏信息点 = 1 | 问自己"这一屏想让观众知道什么"，答不出一个就是多了 |
| 2 | 视觉元素 ≤3 | 数图形/图像/装饰，文案不计 |
| 3 | 文案 ≤12 字（情绪片 ≤8） | 数 |
| 4 | 中文 ≥28px / 拉丁 ≥20px @1080p | 查 tokens |
| 5 | 无硬编码色值 / 字号 / 曲线 | `assert.mjs --stage g3` |
| 6 | 同一时刻位移元素 ≤1 | 看时间轴 |
| 7 | 首帧即有信息 | 渲染第 0 帧看是不是空屏 |
| 8 | 静帧停 3 秒能读完当前文案 | 人眼 |
| 9 | 尾部无死时间（≥15 帧不变） | `assert.mjs --stage g4 --mp4` |
| 10 | 字形覆盖完整 | 运行时 `document.fonts.check(font, 全部文案)` |
| 11 | 无未处理区域（天空外没有纯色面） | `assert.mjs --zoom` 出 4 张 100% 放大图，人眼找纯色块 |
| 12 | 相邻元素完成度差 ≤1 档 | 对照 `references/06` 的档位表逐元素标 |

## 终检六项（G5）

1. 首帧即信息
2. 末帧完整（不是黑屏多挂 2 秒）
3. 全片无死时间
4. 字幕全程可读（压在任何画面上都够对比度）
5. 无硬编码
6. 素材授权可商用

## 画面信息密度（G4，人眼判，机器只备料）

**这一项做不了可靠的自动指标。** 试过用 8×8 灰度缩略图的方差当代理：J-20 那条中位数 42，咖啡那条只有 12.7——太阳和跑道的大光比让"很空"的画面方差反而更高。指标直接反向。

所以机器只做一件事：**自动生成九宫格抽帧**，把审片成本降到一条命令。

```bash
node scripts/assert.mjs --project . --stage g4 --mp4 out/video.mp4 --sheet
# 产出 out/contact-sheet.png
```

判读三条：

1. **任一格主体 <8% 且画面无结构** → 该镜头判负
2. **相邻两格几乎一样** → 节奏停滞
3. **九格里没有一格能单独当封面** → 缺强画面，重做分镜

第 3 条最狠，也最好用：封面级的画面通常是整片唯一被记住的那一格。

## 案例：J-20 起飞（无素材、纯 3D）

| 层 | 现象 | 真因 |
|---|---|---|
| 构图 | 画面空、主体是一小块黑影 | 机位 300 m，主体占 8%→1% |
| 质感 | 半写实、塑料感 | 低模 + 无贴图 + **后处理一项都没有** |
| 主体 | 一望即知"不对" | 观众对歼-20 轮廓高度熟悉，低模 5% 偏差即被识破 |

同一个模型：近景剪影占 60% 时好看，远景半写实占 8% 时难看。**所以不是模型能力，是档位与构图。**

## 丑片诊断表

| 症状 | 根因 | 修法 |
|---|---|---|
| 像 PPT | 元素居中 + 等距 + 同一种动画 | 非对称构图、错峰入场、位移方向不一致 |
| 没有呼吸感 | 满屏元素 | 每镜视觉元素降到 3 个，留白 ≥30% |
| 节奏平 | 每镜时长接近 | 按职能重量重分时长 |
| 字体廉价 | 默认字体 / 一种字重 | 指定字体对 + 字重差 ≥300 |
| 颜色脏 | 多色叠加 | 只留 2 主色 + 1 中性，彩色只用于光 |
| 看不懂 | 一屏多个信息点 | 一屏一件事 |
| 画面抖 | 数字没等宽 / 元素没对齐基线 | 数字用等宽，文字用 baseline 对齐 |
| 廉价发光 | 发光字 + 发光底 | 二选一，或全去 |
| 转场乱 | 用了 3 种以上转场 | 全片只用 1–2 种 |
| 尾重头轻 | 结尾信息量 > 开头 | 把最强的信息提到前 3 秒 |
| 拼贴感 | 多段素材没统一 grade | 加全局 grade + 逐素材曝光系数 |
| 字幕飘 | 文字压动态画面没兜底 | 加文字安全层 |
| 画面空 | 主体占画幅 <8%，或镜头一直看着主体远去 | 换机位 / 上长焦压缩 / 给前景层次 |
| 塑料感 | 半写实档位但没有后处理 | bloom + DOF + 运动模糊 + 颗粒，缺一不可 |
| 一望即知是假的 | 低模撞上观众熟悉形状的主体 | 降到图形化剪影，或换虚构主体 |
| 环境像贴上去的 | 主体做透了，邻接元素只有纯色 | 表面处理：三层叠加，见 `references/06` |
| 建筑像纸板 | 每块面一个颜色，没有基色变化 | 低频噪声 ±8% 明度，成本几乎为零 |
| 场景"有但没画" | 用数量替代质量（7 个机库、90 盏灯都没被决定过） | 每个元素答不出"在画面里干什么"就删 |

## 字形覆盖的正确查法

手写清单会骗人：清单里写了字、字体子集里没有，静态检查照样通过，渲染出来是回退字体。

**唯一可靠的查法在运行时：**

```ts
document.fonts.check('500 40px VideoSerif', 全部文案)  // false = 有字不在子集里
```

第二个参数是文本，浏览器会真的去查 cmap。不通过就 `cancelRender`。

实测：模板自带文案「在这里写文案」不在子集里，画面静默回退成黑体，而 `glyphs.txt` 检查全绿——只有肉眼看图才发现。

## 字体三道坎（实测踩过全部三种）

| 坎 | 现象 | 修法 |
|---|---|---|
| 没加载 | 整屏回退成系统字体，渲染成功 | `FontFace` 显式注册 + `document.fonts.check` + `cancelRender` |
| 加载竞态 | 同一条片子两次渲染一次对一次错 | 同上：禁止用内联 `<style>` 注册字体 |
| 字形缺失 | 加载成功但个别字回退，一行里混两种字体 | 子集由**全部文案的并集**反推，并维护 `glyphs.txt` |

## 断言

```bash
node scripts/assert.mjs --project . --stage g2          # 字体 / 硬编码
node scripts/assert.mjs --project . --stage g3
node scripts/assert.mjs --project . --stage g4 --mp4 out/video.mp4 --copy "全片文案"
```

有 FAIL 时退出码为 1。**不要把 FAIL 解释成"可接受"——五次翻车全是"看起来可接受"。**
