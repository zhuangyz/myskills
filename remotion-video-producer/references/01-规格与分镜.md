# 规格与分镜

G1 的全部产出。目标只有一个：**在写第一行代码之前，把自由度消灭干净。**

## 一、规格卡（brief.md）

八个字段，缺一个就会有对应部分的失控。

| 字段 | 合格填法 | 不合格填法 |
|---|---|---|
| 画布 | 1080×1920 · 30fps · 15s（450 帧） | 竖屏，十几秒 |
| 给谁看 | 25–35 岁城市白领，刷小红书时看到 | 年轻人 |
| 一句标准 | "别像广告，像记录" | 要高级 |
| 节拍 | 4 拍，时长 3/4/4/4 | 开头中间结尾 |
| 视觉系统 | 见 G2，此处只写调性锚 | 蓝色科技风 |
| 运动语法 | 一个元素一种入场 + 一种微动 | 流畅一点 |
| 信息密度 | 每屏不超平台上限（见 04「平台阈值」） | 字别太多 |
| 禁止项 | 纯黑、渐变字、粒子、三种以上字体 | — |

**"禁止项"是性价比最高的一栏。** 模型不知道"高级"是什么，但明确知道"不许发光字叠发光底"。

## 二、节拍表

先有职能，再有镜头。五种通用模型：

| 模型 | 四拍 | 适合 |
|---|---|---|
| 钩子-反差-证明-收口 | 一个动作 / 代价 / 规矩 / 名字 | 品牌片、产品片 |
| 问题-方案-证据-行动 | 痛点 / 解法 / 数据 / CTA | B 端、工具类 |
| 悬念-揭示-放大-落款 | 局部 / 全貌 / 细节 / 品牌 | 新品发布 |
| 倒数清单 | 第 N 名 … 第 1 名 / 品牌 | 榜单、盘点 |
| 单点极简 | 一句话撑全场 | 10 秒以内 |

**四拍时长必须不等。** 3/4/4/4 只是及格，3/4/5/3 才叫有轻重——按字数分配时长会让节奏变平，按职能重量分配才对。

## 三、分镜表（storyboard.md）

七列，缺一列不许进 G3。

| 列 | 内容 | 常见漏项 |
|---|---|---|
| 帧 | 起止帧（不是秒） | 只写秒，实现时换算错 |
| 画面元素 | 图形/图像/装饰，≤3 个 | 把文案算进元素，导致数字虚高 |
| 文案 | 一行一句 | 一镜塞两句 |
| 文案时序 | 第几帧到第几帧入场 | **最容易漏**，导致实现时随便定 |
| 素材契约 | 见下节七项 | 只写"客户提供" |
| **主体占比** | 主体占画幅面积 % + 入画时刻 | **最容易漏，也是粗糙感的第一来源** |
| 运动与转场 | 一个元素两种动作 | 只写"淡入" |

### 示例（可直接照抄结构）

| # | 帧 | 画面元素 | 文案 | 文案时序 | 素材契约 | 主体占比 | 运动与转场 |
|---|---|---|---|---|---|---|---|
| 1 | 0–90 | 底光层 / 等宽数字 / 单位 g | 18 克 | 30–55 淡入 | 纯代码生成 | 55%，第 0 帧即在 | 17.4→18.0，45 帧落定，阻尼回弹；硬切 |
| 2 | 90–210 | 豆落特写 / 单行字幕 | 多一克，就不是这个味。 | 100–140 逐字，每字 2 帧 | 实拍 Mixkit 16:9 / 23.976fps / 18.7s | 满画幅，第 0 帧即在 | 100%→104% 缓推；末 8 帧压黑 |

表头必须一字不差（`assert.mjs --stage g1` 按列名找表）。约定：

- **帧**写成 `起–止`，下一镜的起 = 上一镜的止
- **素材契约**：纯代码镜头写"纯代码生成"；其余必须含比例（`16:9`）和帧率（`23.976fps`）
- **主体占比**写百分比或"满画幅"，加入画时刻；<15% 时写明"强结构"（透视线 / 网格 / 对称轴）或"刻意留白"
- **文案**一格多句用 `<br>` 分隔；无文案写 `—`

## 三之二、主体占比（新增列）

**粗糙感的第一来源不是渲染质量，是主体太小。**

实测：一架 20 米长的飞机，机位 300 米外、fov 45°，只占画幅 8%；背光成剪影后压在同色跑道上，读起来就是"画面很空"。到第 20 秒它加速远去，只剩 1%。同一套几何体，近景剪影（占 60%）好看，远景半写实难看——**模型没变，构图变了**。

| 判据 | 结论 |
|---|---|
| 主体 ≥15% 画幅 | 安全 |
| 8–15% | 需要画面有强结构（透视线、网格、对称轴）分担视觉重量 |
| <8% | 除非刻意留白（且主体有明确指向），否则判负 |

同时必须写**入画时刻**。前 3 秒没有主体 = 钩子失效，观众已经划走。

## 四、素材契约（七项）

只写"谁提供"是不够的。实测：同一图库同一主题的两段素材，一个 1920×1080，一个 1080×1920。

| 项 | 为什么必须写 |
|---|---|
| 谁提供 | 决定 G3 能不能开工 |
| 比例 | 16:9 进 9:16 要裁掉 68% 宽度 |
| 分辨率 | 裁后放大 >1.5× 会明显发软 |
| 时长 | 短于镜头时长要放慢或循环 |
| 帧率 | 23.976 素材进 30fps 时间线，快速动作会重复帧 |
| 主体位置 | 决定能不能裁 |
| 授权 | 商用与否，写进 delivery.md |

## 五、裁切判定

素材进 9:16 前必须回答一个问题：**它是质感还是构图？**

- **质感**（肌理、光影、景深、纹理）→ 可裁，放大也成立
- **构图**（人物、产品、动作关系、空间关系）→ 裁切会毁掉叙事，必须换素材或改版式

实测：豆子特写裁掉 68% 后仍成立，因为它只是肌理；换成手冲壶全景就会裁掉壶嘴和手。

## 五之二、文案登记（spec.json）

分镜定稿的同时，把每一句文案按**用哪个字体渲染**登记进 `src/spec.json`：

```json
{
  "platform": "xiaohongshu",
  "rules": {},
  "copy": {
    "serif": ["18 克", "多一克，就不是这个味。"],
    "mono": ["01 · SINGLE ORIGIN"]
  },
  "holds": [{ "fromSec": 13, "toSec": 15, "reason": "尾板定格" }]
}
```

- `copy` 的键必须与 `tokens.ts` 里 `FONTS` 的键一致——字形覆盖按"这个字体要渲染哪些字"逐字体核对
- 口播字幕写成 `{ "text": "…", "kind": "subtitle" }`，按字幕上限计
- `holds` 登记刻意的定格段（尾板、停顿），死时间检查会豁免；没登记的静止 ≥1s 一律 FAIL
- 分镜里每一句文案都必须能在这里找到，否则 G1 FAIL

## 六、写作记录

分镜表下面必须附一段"为什么这么定"，每条一行。它的作用不是给别人看，是**逼你把直觉翻译成理由**——翻译不出来的决定，通常就是没想清楚的决定。
