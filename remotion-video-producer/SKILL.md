# 视频生产流水线

## 这个 skill 管什么

它**不管 Remotion 的 API**。Remotion 怎么写，官方 Agent Skills 已经覆盖（`/remotion-best-practices` 等）。没装时，按 Remotion 官方文档 AI → Skills 页给出的命令安装；装不上就照 remotion.dev 文档写，不要凭记忆猜 API。

它只负责官方不管的三件事：

1. **顺序**——先规格、后代码，一镜一验，任何时候不许跳步；
2. **门禁**——每道门的通过条件是**可执行断言**，不是"人看一眼"；
3. **品味**——什么算合格、什么算丑、丑在哪、怎么堵。

## 一条铁律

> 凡是写成"检查一下字体对不对"的门禁，都会在某次渲染里悄悄失效。
> 渲染成功从来不等于交付合格——实测多次翻车，退出码全是 0。

所以每道门（G1–G5）都调用 `scripts/assert.mjs`，跑出 PASS / WARN / FAIL / HUMAN。

断言是 **fail-closed** 的：缺输入（没给 `--mp4`、没有 `spec.json`）、缺工具（没有 ffmpeg）、读不懂代码，一律 FAIL。"什么都没查到"不等于通过。HUMAN 表示机器只备了料（九宫格、放大图），判断必须由人做——出现 HUMAN 即结束本轮等放行。

## 三个单一事实来源

| 文件 | 管什么 | 谁读 |
|---|---|---|
| `src/spec.json` | 投放平台（决定节奏 / 字数阈值）、**全部文案**（按字体分组）、豁免的定格段 | 场景代码、`assert.mjs` |
| `src/tokens.ts` | 颜色 / 字号 / 曲线 / 字体文件 / 质感档位 | 场景代码、`assert.mjs` |
| `storyboard.md` | 分镜七列 | 人、`assert.mjs --stage g1` |

文案只在 `spec.json` 写一次。分镜里的文案、场景里渲染的文字、字形覆盖检查都从这里来；场景里直接写中文字面量会被判 FAIL。

## 五条操作准则

1. **规格先于代码。** 没有经确认的 `storyboard.md`、`spec.json` 与 `tokens.ts`，不许创建任何场景文件。
2. **一次一镜。** 整片一次生成必然烂在第 400 行。
3. **静帧验收。** 每镜出起始 / 中段 / 结束三张静帧。看一帧 3 秒，看视频 3 分钟，看代码 30 分钟。
4. **一切落盘。** 规格、分镜、tokens、偏离、验收都是文件。对话会漂移，文件不会。
5. **写实题材先定参考。** 没有参考图就不许调色、不许调雾、不许说"像了"。参考图存进 `reference/`，交付时并排对比。

## 放行规则（硬门禁）

**G1 / G2 / G3 是硬门禁。发出产物后结束本轮，等用户明确放行。**

| 用户说了 | 算不算放行 |
|---|---|
| "过" / "可以" / "继续" / "没问题" / "ok" / "往下" | 算 |
| 沉默、只回"嗯"、只问了别的问题 | **不算**，继续等 |
| "改 X" | 不算——改完重发，仍等放行 |
| "先这样吧" | 不算，追问一句"是定稿还是继续改" |

两条禁令：

1. 不许在同一条消息里发完产物又接着往下做；
2. 不许把"我发了他没反对"当成默认同意。

**G3 的放行粒度**：默认**按拍（节拍表的一拍）批量放行**——一拍内的镜头逐镜做、逐镜跑断言，整拍做完一起发静帧等放行。用户要求逐镜放行时改为逐镜。第一拍无论如何单独放行（它最可能暴露系统性问题）。

G4 只有断言输出 HUMAN（生成了九宫格 / 放大图）时才停，否则无 FAIL 直接进 G5。

## 五道门

### G0 澄清（≤3 个问题）

只问：**给谁看、多长、投在哪个平台**。题材是写实 / 半写实时，第三个问题之后追加一句"有没有参考图"——这不算风格问题，是 G2 的输入。

其余取默认值并在 brief 里标 `假设`。不要问配色、不要问风格形容词——那是对方答不出的问题，答案在 G2 由你推导。

平台决定 `spec.json` 的 `platform`，进而决定最短镜头与文案上限（见 `references/04-质量门.md`「平台阈值」）。用户说"你定"时按题材选，标 `假设`。

产出 `brief.md`（含画布 `宽×高`）。通过条件：三问有答案，或用户说"你定"。

### G1 规格卡 + 分镜

按 `references/01-规格与分镜.md` 填。先有「节拍表」（每拍一个职能），再写「分镜表」。

分镜表必须 7 列齐全：**帧 / 画面元素 / 文案 / 文案时序 / 素材契约 / 主体占比 / 运动与转场**。同时把全部文案登记进 `src/spec.json`。

主体占比低于 8% 且未声明强结构 / 刻意留白时判负——**粗糙感的第一来源是主体太小，不是渲染质量**。
素材契约缺"比例"或"帧率"的镜头，当场标红，不许进 G3。

通过条件：`assert.mjs --stage g1` 无 FAIL，且**用户逐镜确认**（见「放行规则」）。

### G2 视觉系统落地

按 `references/02-token-推导.md` 推导，不套模板、不抄配色。八步走完，落成 `tokens.ts` 并**冻结**。

画面由 3D / 图形生成时，还必须先定**质感档位**（`LOOK.tier`：写实 / 半写实 / 风格化 / 图形化）。档位选错的代价比配色错十倍：半写实缺任何一项后处理就自动塌成"塑料感"。

**所有入画表面必须有材质决定**：纯色面只允许出现在明确选定的剪影档位。环境由 3D 生成时，三层叠加（基色变化 / 磨损 / 污渍）见 `references/06-程序化材质.md`。判据是"相邻元素完成度差 ≤1 档"。

写实 / 半写实档位必须先落参考图 `reference/ref.jpg`。来源优先级：用户给 → 用户认可的公开图（记下出处与授权）→ 都没有时停下问，不许自己编一个"参考"。做法见 `references/07-参考驱动.md`。

先只渲染**一张封面帧**——风格不对此刻改 20 行，做完 15 秒改是重做。

通过条件（`assert.mjs --stage g2` 无 FAIL；写实档位须带 `--compare out/cover.png --ref reference/ref.jpg`）：

- 字体走 `FontFace` 显式注册，不用内联 `<style>` / `@font-face`（消除解析时序竞态）
- 运行时加载断言通过，不通过就 `cancelRender` 让渲染失败
- **字形覆盖由 assert 直接读字体文件 cmap**，对照 `spec.json` 全部文案——运行时 `document.fonts.check(font, text)` 不读 cmap，不能用来查缺字
- 与参考图五项在容差内（写实档位）
- 用户明确放行封面帧（见「放行规则」）

### G3 逐镜实现

一次一镜。每镜完成即渲染起始 / 中段 / 结束三张静帧，过十二项逐镜自检（`references/04-质量门.md`）。

新增任何颜色、字号、缓动、曝光系数、文案 → **先改 tokens / spec.json，不许就地硬编码**。

通过条件：`assert.mjs --stage g3` 无 FAIL，且用户按拍放行（见「放行规则」）。

### G4 装配与节奏

串场、转场、BGM、字幕。只查三件事：**切点密度、镜头时长分布、单屏信息量**。切点直接在成片上检测，与代码怎么组织时间轴无关。

带 `--sheet` 生成九宫格抽帧，人眼判三条：主体占比、相邻格重复、有没有一格能当封面。

通过条件：`assert.mjs --stage g4 --mp4 out/video.mp4 --sheet` 无 FAIL，且 HUMAN 项经用户放行。

### G5 导出与终检

导出后跑 `assert.mjs --stage g5 --mp4 out/video.mp4`（终检六项见 `references/04-质量门.md`），交付 `delivery.md`：画布参数、素材来源与授权、字体清单与授权、Remotion 授权确认、已知限制。

写实档位还要附 `out/compare.png`（参考与成品并排）。

## 停止条件

出现以下情况，停下来问，不要猜：

- 素材分辨率或比例撑不住目标画布（裁切放大 >1.5× 会糊）
- 素材是"构图"而不是"质感"（裁切会毁掉叙事）
- 需要真人 / 写实镜头（超出代码渲染能力，改用视频模型）
- 用户要求"再来一版风格"但没有可判定的差异描述（先出两套 tokens 对比，不要盲改）
- 主体不在素材库，且观众对其形状高度熟悉（飞机 / 名车 / 地标 / 名人）→ 禁止用低模硬扛，改用图形化剪影
- 写实档位没有可用参考图
- 商用主体可能超出 Remotion 免费授权范围（个人与小团队免费，更大的公司需 Company License；条款以 remotion.dev/license 为准，交付前打开核对）
