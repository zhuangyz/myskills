# Three.js 360° 沉浸式场景

把「一个模糊的场景想法」变成一个高质量、离线双击可玩的 360° 可漫游 Three.js 场景。核心方法：**先把想法规格化成六段结构化需求 → 按固定模块逐个程序化实现 → 四机位截图 + 美术评审子 Agent 闭环修到达标**。三个已定稿项目（灯塔小渔港 / 珊瑚礁 / 洪崖洞夜景）证明这条流水线能稳定产出达标场景，本 skill 就是把它们的共性固化。

## 硬性工程规则（任何一步都不许违反）

1. **经典 script，禁 ES module**：要求是"双击 index.html 离线可玩"，而 file:// 协议下 ES module 被 CORS 拦截。用 `<script src>` 顺序加载，three 用 **r128 UMD**（r150+ 无 UMD 构建；UMD 版提前下载放项目 `lib/three.min.js`，不依赖 CDN）。黄金实现 `Codex搜索/灯塔小渔港/lib/` 里就有现成的，新项目直接复制。
2. **一切素材程序化生成**：不用外部图片和模型。纹理用 canvas 画（木纹/岩石/沙粒/斑驳墙），噪声自己实现。
3. **随机数带种子**：全局一个种子（如 `LF.SEED=73129`）的 PRNG，保证每次打开完全一致，也保证评审迭代时改动可归因。
4. **模块分文件**：每个模块一个 js 文件，写完一个向用户汇报一句进度。标准划分见 references/craft-guide.md。
5. **零控制台报错**：交付前 console 必须干净；开发期在 `<head>` 挂 `window.__errors` 钩子捕获 GLSL 静默失败。
6. **页面无 UI**：全屏画布，无标题/按钮/提示/加载文字（调试参数可走 URL query，交付时是干净的）。
7. **性能预算**：远景低面数、近景保细节；DPR 上限 ~1.5；阴影 2048 PCFSoft；后期链控制在 3-4 个 pass。

## 流水线（六步）

**① 规格化** —— 除非用户已给出完整结构化需求（像灯塔那种六段 prompt），否则先读 `references/spec-template.md`，把用户的想法填进六段骨架（风格 / 视角与交互 / 全景构图四方向 / 光照与后期 / 动态效果 / 硬性要求），产出完整规格给用户过目。规格是后续所有实现的验收依据，不能跳过。

**② 脚手架** —— 新建项目目录，复制 `lib/three.min.js`，写 `index.html` + `config.js`（种子、波浪参数、方位约定 +X=东 / -Z=北 / +Z=南 / -X=西）。

**③ 逐模块实现** —— 读 `references/craft-guide.md` 的配方（风格翻译表、地形生成、水面菲涅尔、天空穹顶、自研 postfx 链、交互标准包、动效清单）。按 依赖顺序 写：noise/textures → geom → sky/terrain/ocean → 主题建筑/物体 → ambient（动效）→ controls → postfx → main。

**④ 自检** —— console 零报错；四方向（东南西北）各截一张图自己先看：有没有空白/断面/场景边缘、地平线是否闭环、有没有明显穿帮。

**⑤ 截图美术评审闭环** —— 读 `references/qa-and-pitfalls.md` 的评审协议：固定机位截图 → 派子 Agent 只看图按 P0/P1/P2 列问题 → 修 → 直到 零 P0 且 P1≤2。这是质量达标的必经环节，一般 2-5 轮。

**⑥ 交付** —— 确认双击 index.html 可玩（file:// 验证）、console 干净、定稿截图存 `shots/final-{e,n,s,w}.png`，向用户汇报怎么打开、怎么预览调试。

## 何时不用本 skill

- 用户要的是视频/成片（→ remotion-video-producer）；
- 纯 UI 页面、数据可视化图表；
- 用户明确要用框架（React Three Fiber 等）或要发布到生产环境——本 skill 的产物是单机 demo 形态。
