# 系统性教材学习路线

## 这是什么

用户要啃一本**系统性教材**——有顺序、有练习、通常有贯穿项目的书。**输入有两种**：一个**本地文件夹**（他自己下载好、只留教材内容），或者一个 **epub 文件**。

**下载是用户的活，不是你的活。** 你的活是：把内容摸清楚，然后排出一份学习路线，落成 markdown。唯一的例外是 epub——它是个压缩包，得你先解出正文才能读，见下节。

给的不是笔记，也不是填空问卷，而是：**读什么、跳什么、每章动手做什么、最后要能做出什么。**

和社科那份的关键差别：**社科要拿走骨架，教材要做出东西。** 验收永远是"能做出一个具体的东西"，不是"能讲清楚"。

## 适用范围

**只管系统性教材**：有顺序、有练习、有贯穿项目或习题集的书。

**不管这两类：**

- **API 手册、语法大全、纯参考文档** → 这种根本不用读。告诉用户：建个索引就行，要用的时候查。
- **讲主张的技术书**（讲重构、设计、工程判断那一类）→ 转 `reading-scaffold`，那本要读的是论证，不是路线。

## 在线教材的三个坑（后面的规则都是冲它们来的）

用户手上这份是从网上扒下来的，所以它带着网页版的毛病：

| 坑 | 具体表现 |
|---|---|
| 没有"读完" | 没有页码、没有完成感，最容易点开一堆标签、最后一件事没做成 |
| 练习藏在导航里 | 每章的配套实验折在目录深处，整章跳过都不会有人发现 |
| 答案就在旁边 | 思考题和参考答案在同一份文件里，手一滑就看到了 |

## 先摸清这个文件夹

**动手排路线之前，先把文件夹结构搞清楚。** 不是浏览，是列清单：

1. **找索引**：`mkdocs.yml`、`SUMMARY.md`、`_sidebar.md`、`toc.yml`、`README.md`、`index.md`——有一个就能直接拿到真实顺序。
2. **数正文**：md / ipynb / html / pdf / txt 各有多少，主格式是哪个。
3. **找练习**：`exercises`、`labs`、`实验`、`习题`、`practice` 这类命名的文件夹或文件。
4. **找代码**：配套示例、notebook、可运行的目录。做实验要用，路线里必须标出它在哪。
5. **剔噪音**：`.git`、`node_modules`、`assets`、图片、字体、样式、构建产物——跟要读的内容无关，全部忽略。
6. **防串台**：多语言、多版本的目录（同一本书挂着十几份翻译是常事）→ **只认一种**（默认中文），其余当噪音。走错了整份路线会乱。

**顺序搞不清时**：用文件名前缀（`01-`、`chapter2`）加上每个文件内部的一级标题推。还是推不准，**停下来问用户**，不要瞎编一个顺序。

**每一条都要带相对路径**（比如 `book/chapter3/index.md`），这样读的时候能直接打开文件，不用回头找。

## 如果给的是 epub，先把正文弄出来

epub 就是个 zip 包，正文藏在里面。**这是全流程里唯一你会动手碰用户文件的地方——只解压，原件不许改、不许删。**

macOS 自带 `unzip`、`xmllint`、`python3`（已实测）；`pandoc` 和 Calibre 的 `ebook-convert` 通常**没装**，有就用，**没有不许自己装软件**。

1. **先看里面有什么**（不解压）：`unzip -l 书.epub`
   正常能看到 `mimetype`、`META-INF/container.xml`、一个 `.opf`、`nav.xhtml` 或 `.ncx`，加一堆 xhtml。
2. **找正文包**（不解压）：`unzip -p 书.epub META-INF/container.xml`
   里面的 `full-path` 指向 `.opf`。路径不一定是 `OEBPS/content.opf`，**以它写的为准**。
3. **拿元数据和真实顺序**（不解压）：
   `unzip -p 书.epub <opf路径> | xmllint --format - | grep -E 'dc:(title|creator|language|date)|itemref'`
   - `dc:title`、`dc:creator`、`dc:language`、`dc:date` → **顺手抄进路线文件顶部**，比问用户强。
   - **`<spine>` 里的 `itemref` 顺序才是真正的阅读顺序**，文件名基本不可信（`part0012.html` 这种是转换工具随手起的，`ch2` 排在 `ch1` 前面很常见）。
   - 章节**标题**从 `nav.xhtml` 或 `.ncx` 的目录里取，不许从文件名猜。
4. **要读正文了才解压**：`unzip -o 书.epub -d "<书名>_文本/"`
   解在 epub 旁边，别塞到别处。解完告诉用户放哪了，他不要可以删。
5. **有 pandoc 或 Calibre 就用**：直接转成一个 markdown，比几百个 xhtml 好读太多。没有就按上面走。

**三条忌讳：**

- **不许整本倒进上下文。** epub 几十万字很常见。先读 `.opf` 拿元数据和顺序，排完路线，再按需读具体章节。
- **不许靠文件名排顺序**，一切以 `<spine>` 为准。
- **解不开就是解不开。** 带 DRM 的商业电子书正文是加密的，解压出来的 xhtml 读不出内容。遇到就直说"这本有 DRM，我拿不到正文"，请他改给文件夹或 PDF——**别硬凑一份路线**。

## 起手动作

**输入是文件夹路径，或者一个 epub 文件。** 文件夹就按上一节摸清它；epub 就按上上节先把正文弄出来。两种情况都要**从内容里读出真实的目录和章节标题**——不要凭记忆，也不要叫用户报。

用户给的是链接或只报书名、手上还没有文件夹 → 一句话说清约定：**"你先下好、只留教材内容，把文件夹路径给我。"** 别自己开始爬。

摸清之后，把这四样看明白：

1. 有没有"如何阅读本书 / 前置知识"这类引言——**有就先读它**，别从第一章开始。
2. 每章有没有配套实验 / 练习 / 习题——扫一遍文件名就有准数，比翻目录可靠。
3. 配套代码在哪。
4. 前置知识够不够——不够就在路线里加一条"先补 X"，别让用户硬啃。

然后**必须问两个问题**，各一句话就行：

1. **你想用它做出什么？**（目标）
2. **你现在什么水平？**（没碰过 / 会一点 / 有经验但没系统学过）

这两个必须问，因为**教材是目标驱动的**：不知道你要做什么，就排不出"哪几章现在读、哪几章留索引"。文件夹的结构我扫得出来，目标只有你知道。

## 铁律

1. **不抄 API。** 不许把函数名、参数、语法清单搬进来——那是文档的活。这份只给路线、产物、验收。
2. **先跑起来。** 配套实验先跑，再读正文——顺序反了，你会读完一章却什么都没做出来。
3. **思考题先自己写，再看参考答案。** 答案就躺在同一个文件夹里，所以这条必须写在脸上。参考答案是验收用的，不是阅读用的。
4. **章节名和相对路径照抄文件**，不许改写、意译、凭记忆。
5. **目标驱动，不按目录顺序推。** 离目标远的章节直接标"留索引"或"跳过"，不客气。作者自己标了"可选阅读"的，尊重那个标记。
6. **每一章都要有一个动手产物。** 没有产物的章节，不许出现在"现在读"里。
7. **要有明确的终点。** 本地读没有漫游问题了，但"读完"依然不存在——写清楚什么时候可以停、停的时候手里该有什么。
8. **验收是能做出来的东西**，不是"理解了""掌握了"。
9. **不要求用户记住。** API 忘掉是对的。产出物是路线 + 速查表，不是笔记。
10. **只在文件夹里加你那一份文件**，不许顺手改、删、整理用户下好的内容。
11. **一页纸左右。** 长了不会用。

## 输出模板（照这个填，标题就是书名）

````markdown
# 《书名》· 学习路线

- 来源：______（教材文件夹路径 / epub 文件路径）
- 正文：主格式 ______，共 ______ 篇（epub 解出的文本在 ______）
- 书名 / 作者：______　出版日期：______
- 配套实验在哪：______　配套代码在哪：______
- 快照：下载日期 ______（文件夹本身是 git 仓库就再记 commit ______）
- 我的目标：______（要做出什么）
- 我现在的水平：______
- 开始：______　打算什么时候收工：______

## 一、先做这三件事（半小时以内）

- [ ] 读它的"如何阅读本书 / 前置知识"：______（路径）
- [ ] 找到配套代码，跑通一个最小例子：______
- [ ] 翻一遍目录，标出跟我的目标有关的章：______

## 二、读什么、跳什么

| 章 | 标题 | 路径 | 现在读 / 留索引 / 跳过 | 为什么 |
|---|---|---|---|---|
| 1 | | | | |

> 留索引 = 不读。知道它在哪、讲什么，要用的时候按路径回来查。

## 三、每一章的动作

| 章 | 配套实验 / 练习（先跑这个，再读正文） | 我自己要动手做出来的东西 | 做完 |
|---|---|---|---|
| 1 | | | [ ] |

## 四、思考题（先自己写，写完再看参考答案）

| 章 | 我的答案（自己写，不许先看答案） | 对完答案，我想错在哪 |
|---|---|---|
| 1 | | |

> 没有思考题就写"无"，别留一张空表。

## 五、速查表（边读边补，没读到的先空着）

| 我想做 | 在哪一章（路径） | 关键概念 / 函数 | 我踩的坑 |
|---|---|---|---|
| | | | |

## 六、验收（这一段做完，这次阅读就算完了）

从零做出：______

- [ ] 不再翻资料能做出来
- [ ] 故意改坏一次，看得懂报错
- [ ] 再加一个书上没有的小改动
- [ ] 把踩的坑补进第五部分
````

## 怎么排"读什么、跳什么"

- **从目标倒推**：目标需要哪几块能力 → 找出对应的章 → 只留这些，其余留索引。
- **必修的地基**（不懂就读不下去的前置章）标"现在读"。
- **查语法、列参数、查配置**这类章节一律"留索引"。
- **有经验的用户**：基础章可以跳，但要先做一遍那章的产物确认真的会，再跳。
- 目标是"做出一个小东西"时，路线要**尽早让东西跑起来**，别等基础全学完。
- 纯新手：路线连续、不跳，每章产物压到最小（二十行级别，能跑就行）。

## 落盘规则

- **位置**：给的是文件夹 → 就放在**文件夹里**，叫 `学习路线.md`，打开就能看见它，跟正文挨着。给的是 epub → 放在 **epub 旁边**，叫 `《书名》学习路线.md`。用户指定别处就听他的（同书多版或同名书要带版次或作者）。
- **文件顶部记全**：文件夹绝对路径、正文格式和篇数、实验和代码在哪、下载日期（有 git 就带 commit）。
- **文件已存在** → 不许覆盖。先读一遍，再问用户是接着用还是新起一份。
- **只写路线和空位**，不预填用户的答案（目标、坑、思考题答案都是他的）。把他的回答写回文件时，问题原文留在上面。
- 写完把**完整路径**报给用户。

## 边界情况

- **用户报的是 API 手册 / 纯参考文档** → 不生成路线，直接说这类不用读，建索引就行。
- **用户报的是讲主张的技术书** → 转 `reading-scaffold`。
- **用户给的是链接或书名、还没有文件夹** → 说清约定："你先下好、只留教材内容，把文件夹路径给我。"别自己开始爬。
- **epub 解不开 / 正文是加密的** → 这本有 DRM，直说拿不到正文，请他改给文件夹或 PDF，**别硬凑路线**。
- **epub 里全书挤在一个 xhtml**（转换质量差的常见） → 按文件里的 `<h1>` / `<h2>` 切章，别当成"只有一章"。
- **用户给的是 mobi / azw3** → 需要 Calibre 转换，机上多半没有；直说，请他转成 epub 或 PDF。
- **epub 有几百个小文件**（有的转换器一节一个文件） → 按 `<spine>` 归并成"章"，别把每个文件当成一章，否则路线会长到不能用。
- **文件夹里混着多语言 / 多版本** → 只认一种（默认中文），其余当噪音，并在文件顶部注明取了哪一份。
- **文件夹里混着代码、图片、构建产物** → 正文照扫，噪音忽略；但**配套代码的位置要单独标出来**，做实验要用。
- **只有 PDF、没有源文件** → 按 PDF 的目录或书签排，章节名从目录抄；页码也写进路线，方便翻。
- **路径不存在或读不了** → 直说，请他核对路径。
- **顺序推不准** → 停下来问，别编。路线错一步，后面全歪。
- **用户说不出目标** → 只问这一句，别硬排；他真不要目标，就给一份"通读版"，并在文件里标明这份没有取舍、会慢。
- **用户只想查某一章** → 直接给那一章的产物和验收，不生成整份。
- **用户嫌某个部分没用** → 直接删那一栏，不辩护。这份是他的工具。
