> 用法：**任务状态放在编排器，运行状态放在这里。** 断线后不依赖任何会话记忆，只靠这两份文件 + 工作区实际 diff。
> 每次任务开始前、结束后各更新一次；父 Agent 崩溃/断线前的最后一次写入就是恢复的唯一起点。
> 完成标准：新会话拿到这份文件，能在不产生第二个写入者的前提下续跑。

| 旧 subagent 是否可能仍在运行 | <是 / 否 / 未知> |

规则：

- **租约有效**（当前时间 < 租约截止时间）→ 不启动任何新的写入者，等待或向用户确认。
- **租约过期**且工作区已停止变化（工作区指纹在观察窗口内不变）→ 才允许把任务移交给恢复 subagent。
- 移交前先确认旧 subagent 状态；无法确认时按"保守等待 + 向用户确认"处理。

## 4. 中断分类与处置

| 现象 | 分类 | 处置 |
| --- | --- | --- |
| 连接失败 / 503 / 超时 | 短暂故障 | 不标阻塞；确认无运行中的写入者后续跑 |
| 会话被终止 | 运行中断 | 按 §1 租约规则判定；先复核部分修改归属 |
| 任务本身无法继续 | 业务阻塞 | 标记阻塞，写清问题与需要用户回答的具体问题 |
| 依赖缺失 / 编译失败 | 技术故障 | 自行修复；超重试上限再升级 |

## 5. 恢复步骤

1. 读取本文件 + `02-任务编排器.md`。
2. 确认**没有仍在运行的写入型 subagent**（否则等待）。
3. 校验租约；未过期则不得启动新写入者。
4. 检查工作区实际 diff，判定未完成改动属于哪个任务、是否可续。
5. 处理部分修改：可续 → 交回原任务；不可续且已污染 → 回退到干净状态再重做（记录回退理由）。
6. 从第一个"依赖已满足且未完成"的任务续跑；已完成的步骤**不重复执行**（幂等）。
7. 恢复后补写上一轮缺失的变更日志与交付说明。

恢复启动指令：

```text
读取 <路径>/05-执行恢复检查点.md 与 02-任务编排器.md，检查上一次执行是否完成。
先确认没有仍在运行的写入型 subagent，再根据检查点、任务状态和工作区实际 diff 决定续跑或返工。
```
