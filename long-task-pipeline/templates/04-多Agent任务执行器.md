# <主题> 多 Agent 任务执行器

关联：[开发计划](01-开发计划.md) · [任务编排器](02-任务编排器.md) · [执行恢复检查点](05-执行恢复检查点.md)

## 1. 启动指令（用户直接复制）

```text
按照 <路径>/04-多Agent任务执行器.md 执行 <主题> T01–T0N。

你是父 Agent，只负责任务编排、状态管理、验收和阻塞处理。每个开发任务必须交给 subagent 完成。
一次只运行一个会修改工作区的开发 subagent。
从 02-任务编排器.md 中第一个依赖已满足的"待执行"任务开始，持续执行到所有任务完成或出现必须由
用户确认的阻塞。不要在完成单个任务后结束整个会话。
```

启动前确认：

- [ ] 工作目录是项目根目录
- [ ] 真源工具已连接且可访问（设计 MCP / 接口文档 / 源文件）
- [ ] 没有其他 Agent 同时修改这个工作区
- [ ] 已记录工作区基线：`git status --short`（基线内的用户改动全程保护，不得回退或覆盖）

## 2. 角色与边界

| 角色 | 做 | 不做 |
| --- | --- | --- |
| 父 Agent | 维护任务表、下发任务单、验收、派发返修、升级阻塞、派发集成验收、最终收口 | 不自己写业务代码 |
| 开发 subagent | 按任务单实现、自检、按格式回报 | 不越界改文件、不扩范围、不依赖父会话历史 |
| 集成验收 subagent | 全部完成后只读复核 | 不修代码 |

## 3. subagent 创建规则

```text
subagent({
  task_name: "t01_<slug>",
  fork_turns: "none",
  message: "<完整任务单>"
})
```

- **固定 `fork_turns: "none"`**：不继承父会话上下文。所有必要上下文由任务单 + 仓库文档 + 真源提供。
- 开发 subagent 与集成验收 subagent 使用相同设置。
- subagent 自行读取：本任务卡、开发计划、流程与状态路由、`AGENTS.md`、项目开发规范、领域术语表、真源节点。

## 4. 任务单模板（父 Agent 每次下发）

```text
你是 <任务> 的开发 subagent。你没有继承父会话历史，以下信息即全部上下文。

任务：<T0N 名称>
任务卡：<路径>（先完整读它）
真源：<节点/章节标识>（必须现场读取，禁止使用历史输出或本地转录）
依赖：<T0X 已完成 / 无>
允许修改的文件：<列表>
工作区基线：会话开始前已有未提交改动 <列表/无>，不要碰它们。
非目标：<…>

完成后按任务卡 §7 的回报格式回复。
```

## 5. 回报与验收

- 回报必须结构化（状态 / 改动文件 / 真源读取记录 / 自检命令与结果 / 验收项 / 遗留问题）。
- 父 Agent 验收顺序：① 回报完整性 → ② 与任务卡验收项逐条对齐 → ③ 实跑自检命令 → ④ 确认改动范围未越界 → ⑤ 更新任务表状态。
- **验收失败 → 返修模板**：

```text
T0N 验收未通过，问题如下：
1. <问题 + 期望>
2. <…>
请仅修复以上问题，不要改动其他文件，也不要扩范围。修复后按原格式回报。
```

返修一律交回**原 subagent**（它有上下文）；不要新起 subagent 从头理解。

## 6. 集成验收

全部任务完成后，派发一次独立只读复核：

```text
你是集成验收 subagent，只读，不修改任何文件。
范围：<主题> T01–T0N 的全部产出。
检查：① 主链路端到端可走通；② 跨任务命名/路由/状态一致；③ 无残留旧命名与占位实现；
④ 与真源现场比对关键页面；⑤ 关键路径可启动/可构建。
输出：通过项、未通过项（附文件与依据）、建议返修任务。
```

## 7. 中断恢复

父 Agent 在每个任务开始前、结束后各更新一次 [执行恢复检查点](05-执行恢复检查点.md)（当前任务、运行编号、所有权令牌、租约截止时间、进度、工作区指纹）。

- 短暂连接失败/503/超时：**不标记任务为阻塞**，按检查点续跑。
- 租约有效期内不启动新的写入者。
- 恢复前必须先确认旧 subagent 是否仍在运行。

## 8. 最终收口

- [ ] 全部任务为终态（已完成 / 已阻塞并说明）
- [ ] 集成验收通过
- [ ] 任务表、任务卡、路由文档、检查点相互一致
- [ ] 写变更日志
- [ ] 输出交付说明：已完成 / 未完成（含原因）/ 下一步
