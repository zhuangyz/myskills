| 任务 | 名称 | 依赖 | 状态 | 产出 | 通过门槛 |
| --- | --- | --- | --- | --- | --- |
| T01 | <名称> | 无 | 待执行 | <页面文件 / 路由 / 测试> | <可勾选的验收项 + 自检命令> |
| T02 | <名称> | T01 | 未开始 | <…> | <…> |
| T03 | <名称> | T01 | 未开始 | <…> | <…> |

状态取值（只允许这 6 个）：

| 状态 | 含义 |
| --- | --- |
| 未开始 | 依赖未满足 |
| 待执行 | 依赖已满足，可被父 Agent 领取 |
| 进行中 | 已派发给 subagent |
| 已完成 | 通过门槛 + 父 Agent 验收通过 |
| 阻塞 | 需要用户确认或外部条件（见 §3） |
| 失败待返修 | 验收未通过，已派回原 subagent |

## 2. 执行顺序与并发

- 默认**串行**：同一时间只运行一个会修改工作区的开发 subagent（上下文独立、工作区共享）。
- 只读 subagent（检索、复核、集成验收）可与写入者并行。
- 可并行条件（同时满足才允许）：互不修改同一文件、无依赖关系、产出可分别验收。满足时在表中标注 `并发组：G1`。

推荐执行序：

```text
T01 → T02 → T03 → … → T0N → integration_review
```

## 3. 阻塞条件与升级路径

区分两类，处置完全不同：

- **业务阻塞**（允许停）：设计缺失、需求冲突、需要用户决策、需要账号/授权/环境。→ 标记 `阻塞`，写清问题、已尝试的方案、需要用户回答的具体问题，然后停止等待。
- **技术阻塞**（不允许停）：编译错误、依赖缺失、真源读取失败、测试失败。→ 自行排查修复；确实无法解决且超过既定重试次数，才升级为业务阻塞。

真源读取失败必须阻塞，**禁止用历史输出、本地转录或猜测代替现场读取**。

## 4. 通过门槛（每个任务通用）

1. 真源现场读取完成，并在回报中列出实际读取的节点/章节。
2. 实现范围与任务卡一致，未越界修改其他任务的文件。
3. 项目自检命令通过（格式化 / 静态分析 / 相关测试）。
4. 与真源逐项比对通过（元素级，不是"看起来对"）。
5. 无残留旧命名、无占位实现（`TODO` 需登记为后续任务）。
